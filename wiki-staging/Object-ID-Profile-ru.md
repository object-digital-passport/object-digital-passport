# Профиль Object ID — документирование для возврата

> [🇬🇧 English](Object-ID-Profile) · 🇷🇺 **Русский**

[Object ID](https://icom.museum/en/resources/standards-guidelines/objectid/) — международный чек-лист (ICOM), по которому музеи, полиция, ИНТЕРПОЛ и страховые описывают культурные объекты, чтобы их можно было опознать и вернуть после кражи. Начиная с **v0.6** ODP не просто *умеет нести* этот чек-лист — модель данных паспорта *построена на нём*: категории опознания стали полноправными полями и якорями, с криптографической меткой времени.

> ODP *совместим с* чек-листом Object ID. Проект не аффилирован с ICOM и не сертифицирован им.

## Один документ — две задачи

- **Подлинность:** хэши, якоря и институциональные подтверждения отвечают на вопрос «передо мной зарегистрированный оригинал?»
- **Возврат:** чек-лист отвечает на вопрос «можно ли опознать объект, если он исчезнет?» — а те же *отличительные особенности* (тот самый отреставрированный разрыв, та пометка мелом на подрамнике) помогают эксперту отличить оригинал от копии. QR-код подделыватель склонирует; задокументированный трёхсантиметровый ремонт — уже вряд ли.

## Девять категорий → поля паспорта (v0.6)

| Object ID спрашивает | Где это в паспорте |
| --- | --- |
| Тип объекта | `domain` + `objectType` (также `physical.category`) |
| Материалы и техника | якорь `materials` (плюс `physical.medium`) — для физических объектов **обязателен** |
| Размеры | якорь `dimensions` — для физических объектов **обязателен** |
| Надписи и клейма | якорь `marks` |
| **Отличительные особенности** | якорь `distinguishing_features` — **обязателен**; повреждения, ремонты, дефекты — пишите так, чтобы посторонний мог сверить |
| Название | `title` — лежит прямо **on-chain** в карточке паспорта |
| **Сюжет** (что изображено) | `shortDescription` (карточка on-chain) и полное `description` |
| Дата или период | `creationDate` |
| Автор | `authorName` (карточка on-chain) + `authorship.author` |
| + Фотография | якорь `photo` — для физических объектов **обязателен** |

Все факты опознания собраны в одном блоке `anchors[]` внутри `passport.json`, отпечаток которого хранится on-chain как `anchorsHash`. Контракт **откажется выпускать** паспорт физического объекта без жёсткого минимума: фото + размеры + материалы + отличительные особенности. Так что каждый паспорт v0.6 — документация «уровня возврата» по построению, а не по доброй воле.

## Держите в секрете, пока не понадобится

Практика Object ID: документацию хранить надёжно и раскрывать по инциденту. ODP это умеет из коробки:

1. Минтите с **пустой публичной ссылкой** — в блокчейн уходят только отпечатки; фото и особенности остаются в вашем приватном `.odpass`.
2. Если объект украден — передайте `.odpass` полиции и реестрам (или опубликуйте).
3. Любой сможет сверить документацию с **докражными** on-chain отпечатками и меткой времени: описание доказуемо не придумано задним числом.

И никогда не пишите адрес хранения объекта в публичные on-chain данные — события местонахождения публичны навсегда, записывайте только огрублённые значения ([правило приватности](https://github.com/object-digital-passport/object-digital-passport/blob/main/SPEC.md#immutable-core-vs-append-only-events-normative)).
