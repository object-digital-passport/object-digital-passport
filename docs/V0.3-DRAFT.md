## 2) Classification and terminology sync (proposal)

### 2.1 Canonical terms

- **Passport ID** (human-readable concept) maps to protocol field **`humanId`**.
- **Profile ID** (human-readable concept) maps to protocol field **`creatorId`**.

### 2.2 Classification matrix to keep aligned

- **Issuer class**: `C`, `B`, `P`, `M` (already in v0.2).
- **Object class**: physical / digital (already in v0.2).
- **Proof issuer eligibility**: `P` and `M` (already in v0.2).
- **Affiliation relationship class** (proposed): `P_PARENT_CHILD` with lifecycle events.

### 2.3 "Sync everywhere" checklist

If this proposal lands, update all public surfaces in one pass:

1. `SPEC.md` (normative terms and event/field definitions).

## 3) Multiple images per passport (proposal)

### 3.1 Product need

Some objects need more than one image (front/back/detail/macro/provenance page).  
Current v0.2 stores a single `imageHash` + `imageUrl` on-chain.

### 3.2 Candidate v0.3 options

**Option A (strict and cheaper):**
- Keep one canonical on-chain `imageHash` for backward compatibility.
- Add optional off-chain `images[]` list in `passport.json` (up to N items).
- Each item contains URL + hash metadata; the chain still anchors via `dataHash`.

**Option B (richer on-chain support):**
- Add bounded on-chain image array (e.g., max 3 or max 5).
- Store per-image hash and optional URL pointer.
- Expose paged getters and ABI structs for verifier UI.

### 3.3 Draft recommendation

- Start with **max 3** (default recommendation) and allow governance decision to raise to **5** before freeze.
- If gas impact is too high, prefer Option A for v0.3 and keep Option B for a later line.

### 3.4 Data model sketch (if Option B)

- `imageCount` (uint8, max 3 or 5).
- `images[i].imageHash` (bytes32, required when slot is used).
- `images[i].imageUrl` (string, optional, URL constraints aligned with `dataUrl` policy).

## 4) P-parent can detach child P (proposal)

Current v0.2 affiliation flow is child propose + parent confirm.  
This draft adds explicit **detach** by the current parent.

### 4.1 Proposed actions

- `proposePRelation(parent, child)` (existing logical step).
- `confirmPRelation(parent, child)` (existing logical step).
- `detachPRelation(parent, child, reasonCode?)` (new).

### 4.2 Safety constraints

- Only current recorded parent can detach.
- Child can still re-attach to another parent via normal proposal/confirm flow.
- Detach is explicit and auditable (event + timestamp).

## 5) Mandatory relationship timestamps and audit trail (proposal)

Add timestamps and event history for all affiliation lifecycle transitions:

- `joinedAt` — when relation became active (confirmation time).
- `detachedAt` — when relation was terminated (if terminated).
- `updatedAt` — latest lifecycle update time.
- Optional `reasonCode` for detach (bounded enum/string policy in spec draft).

### 5.1 Event-level history

Emit dedicated events with UTC epoch timestamps:

- `PRelationProposed(...)`
- `PRelationConfirmed(..., joinedAt)`
- `PRelationDetached(..., detachedAt, reasonCode)`

### 5.2 UI / docs behavior

- Show current status: active / detached / never-linked.
- Show "since" date for active links.
- Show detach date and reason where available.
- Preserve history in verifier view (not only latest state).

## 6) Carry-over ideas from v0.2 draft (not yet implemented)

The following topics from **[`V0.2-DRAFT.md`](V0.2-DRAFT.md)** remain open and are carried into this v0.3 draft backlog:

## 7) Rollout notes for future implementation

If the v0.3 feature set is accepted:

- Define exact ABI and migration strategy in `SPEC.md`.
- Add contract-version gate in `web/odp-contract.js` and fallback behavior for older deployments.
- Update verification logic for multi-image and relation history views.
- Update security guidance for new attack surfaces (spoofed image sets, stale relation status, replayed detach metadata).

---

## 8) Out of scope for this draft

- Immediate protocol change in the current v0.2 mainnet deployment.
- Backporting new v0.3 fields to historical v0.1/v0.2 contracts.
