# Лимит байткода EIP-170 — стратегия для `ObjectDigitalPassport`

*Перевод справочно. Нормативный оригинал — только на английском: [`docs/EIP170_STRATEGY.md`](../EIP170_STRATEGY.md). Этот текст может содержать ошибки; при расхождении верен английский.*

Правило Ethereum **Spurious Dragon** ограничивает **байткод создания контракта** **24576 байтами**. Polygon PoS этот лимит наследует.

## Текущее положение

- Деплоимая эталонная линия использует **разделённую архитектуру**:
  - основной реестр: [`chain/contracts/ObjectDigitalPassport.sol`](../../chain/contracts/ObjectDigitalPassport.sol)
  - линкуемая библиотека: [`chain/contracts/ODPPassportLib.sol`](../../chain/contracts/ODPPassportLib.sol)
  - спутники: [`chain/contracts/ODPRegistryRelations.sol`](../../chain/contracts/ODPRegistryRelations.sol), [`chain/contracts/ODPPassportProofRegistry.sol`](../../chain/contracts/ODPPassportProofRegistry.sol), [`chain/contracts/ODPExtensionMintRouter.sol`](../../chain/contracts/ODPExtensionMintRouter.sol), плюс опциональные спутники якоря документов и заявлений о подделке
- При оптимизаторе `runs: 1` и `viaIR: true` (см. [`hardhat.config.ts`](../../chain/hardhat.config.ts)) **основной реестр** рассчитан оставаться **≤ 24 КиБ**. Запустите `npm run compile` из корня репозитория и посмотрите строку **`[ODP] EIP-170:`** до публичного деплоя.
- Сеть **Hardhat** настроена с **`allowUnlimitedContractSize: true`**, чтобы локальные тесты запускались; к публичным сетям это **не** относится.

## До любого деплоя в mainnet или Amoy

1. Запустите `npx hardhat clean && npm run compile` из корня репозитория и посмотрите вывод компилятора и размер артефакта (или используйте `hardhat-contract-sizer`, если добавите его).
2. Если размер превышен, выберите один вариант или их сочетание:

### Вариант A — ужать монолит

- Ещё понизить `runs` оптимизатора, пересмотреть дублирующуюся логику, сократить использование пользовательских ошибок — но только если это помогает (строк в `revert` и так нет).
- Убрать или закрыть за условием редко используемые пути кода — только если продукт согласен.

### Вариант B — контракты-спутники

- Предпочтительный эталонный подход для v0.5+: держать ядро создателей и паспортов на основном реестре, а опциональные и ортогональные поверхности выносить в спутники с явной привязкой к тому же адресу реестра.

### Вариант C — новая линия деплоя

- Заморозить текущий байткод для архива; выпустить **v0.4+** как более тонкую или разделённую архитектуру по **новому адресу** (без автоматической миграции).

## Политика

- **Не** рассчитывайте на `allowUnlimitedContractSize` в продакшене.
- Любая новая возможность в цепи (уникальный `dataHash`, проверка ECDSA) обязана включать **бюджет по размеру** в ревью.
