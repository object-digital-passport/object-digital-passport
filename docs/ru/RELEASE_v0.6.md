## Кратко

**v0.6** — редизайн «с нуля» того, что хранит паспорт и где, выстроенный вокруг **принципа опознания Object ID**. Каждый паспорт теперь несёт небольшую неизменяемую **карточку в цепи** (`title`, `authorName`, `shortDescription`, `domain`); разрозненные поля v0.5 под пломбы, дополнительные изображения, материалы, размеры и маркировки заменены одним расширяемым массивом `anchors[]`; а каждое ранее перезаписываемое поле текущего состояния стало **append-only событием**. В этот тег входят также опциональный спутник `ODPAuthorAttestation` (подтверждение автора по EIP-712, теперь развёрнут), переписанная JSON Schema под новую форму и полностью перепереведённый русский `SPEC.md`.

## В цепи (протокол)

- **Карточка в цепи:** `title`, `authorName`, `shortDescription`, `domain` записываются один раз при минте, **пути редактирования нет** — опечатка или переименование означают отзыв и переминт. ОБЯЗАНЫ совпадать с `passport.json` байт-в-байт; верификатор, нашедший любое расхождение, сообщает о паспорте как о **подделанном**, а не просто изменённом.
- **Якоря идентификации:** единый массив `anchors[]` (`photo`, `dimensions`, `materials`, `distinguishing_features`, `marks`, `file_hash`, `perceptual_hash`, `c2pa`, `nfc`, `numbered_seal`, `fingerprint`, `dna`, …), зафиксированный в цепи через `anchorsHash` + `anchorTypesMask`. При минте принуждается **жёсткий минимум идентификации** по `objectType`: физическим объектам нужны `photo` + `dimensions` + `materials` + `distinguishing_features`, цифровым — `file_hash`. Криптографическая пломба (`nfc` / `numbered_seal`) теперь **опциональна** поверх этого минимума.
- **Append-only события:** `recordPassportEvent` заменяет все перезаписывающие сеттеры текущего состояния из v0.5 — статус, местонахождение, права, состояние, повреждение, реставрацию или произвольную заметку, каждая с опциональным якорем подписанного документа по хэшу. Текущее значение любого изменяемого аспекта — это просто последнее событие своего вида.
- **`freeze()` возвращён:** необратимый предохранитель остановки записи, доступный только деплоеру, существовал вплоть до v0.4, был убран в линии v0.5 ради бюджета байткода EIP-170 и вернулся в v0.6.
- **Уровни защиты** (Base / Sealed / Attested): сводка проверок §11 SPEC на уровне отображения, вычисляемая в момент просмотра из текущего состояния в цепи — она никогда не хранится в цепи, не кодируется в идентификатор и не печатается на объекте.
- **Канонический реестр:** развёрнутый реестр v0.6 теперь является нормативной целью по умолчанию для неуточнённых ссылок `odp://` (SPEC §7, §12.3, §19.2); другие деплои обязаны называть себя сами.
- **Спутник `ODPAuthorAttestation` (новый, развёрнут):** опциональное подтверждение автора по EIP-712, привязывающее отдельный ключ автора к `dataHash` и `creatorId` паспорта независимо от кошелька, отправившего транзакцию минта. Выпущен именно спутником, чтобы байткод основного реестра остался нетронутым: его принятие не потребовало передеплоя канонического реестра, и адрес реестра не сдвинулся.

## Байткод (EIP-170)

Удаление шести перезаписывающих функций и крупного куска структуры с запасом окупает новые поля карточки и якорей: основной реестр теперь компилируется в **13 309 байт** против лимита в 24 576 — примерно половина бюджета свободна под будущую работу над протоколом.

## Документация, схема и локализация

- **`schema/passport-0.6.schema.json`** заменяет схему v0.5 как ту, по которой валидирует CI; примеры переписаны под форму v0.6 (поля карточки плюс `anchors[]`), а правила `allOf`/`contains` принуждают тот же жёсткий минимум идентификации, что и контракт.
- **`docs/SECURITY.md`** (и русское зеркало) переписан под модель угроз v0.6, включая таблицу разбора находок статического анализа (Slither).
- **`ru/SPEC.md`** полностью перепереведён, раздел за разделом, вслед за английским `SPEC.md` версии v0.6 — до этого он застрял на описании формы v0.5.
- **`CHANGELOG.md`** добавлен в корень репозитория (формат Keep a Changelog), покрывает каждый выпущенный тег плюс эту линию.

## Что куда переехало (v0.5 → v0.6)

| v0.5 | v0.6 |
| --- | --- |
| только числовой ID профиля, в цепи | + карточка в цепи: `title`, `authorName`, `shortDescription`, `domain` |
| `sealType` / `sealHash` / `nfcPublicKey` / `nfcModel` | якоря `nfc` / `numbered_seal` |
| `imageHash2/3`, `imageUrl2/3` | якоря `photo` (без фиксированного лимита) |
| `currentState.*` плюс четыре перезаписывающих сеттера | append-only `recordPassportEvent` |
| `auxCommitment*` (указатель на COA) | `documentHash` подтверждения либо якорь-документ |
| `ndppCommitment*` | офлайн-носители сверяются напрямую с `dataHash` / `anchorsHash` |
| `physical.seal` / `image` / `images` в JSON | `anchors[]` |

Профили (C/B/P/M), месячные лимиты минта, делегирование агенту минта, спутники отношений, доказательств и заявлений о подделке, отзыв, передача владения и обновление URL по модели не изменились.
