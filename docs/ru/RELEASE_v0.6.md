# ODP v0.6 — редизайн модели хранения

*Перевод [`docs/V0.6.md`](../../docs/V0.6.md). Нормативный текст — [SPEC.md (EN)](../../SPEC.md).*

ODP v0.6 — редизайн «с нуля» того, что хранит паспорт и где. Стандарт заново выстроен вокруг **принципа опознания Object ID** — тех же категорий, которыми музеи и страховщики идентифицируют объект (тип объекта, материалы и техника, размеры, надписи и маркировки, отличительные особенности, название, сюжет, дата/период, автор, плюс фотографии и краткое описание), — и делает эти категории первоклассной частью модели данных, а не необязательной добавкой. Обоснование и полные таблицы полей — в [`docs/REQUIREMENTS_FIELDS_V0.6.md`](../../docs/REQUIREMENTS_FIELDS_V0.6.md) (на русском); нормативные правила — в `SPEC.md`.

Каждая линия 0.x — отдельный реестр. v0.6 выпускает паспорта с упакованным `CONTRACT_VERSION = 6` и **не** совместим назад с ранними деплоями.

**Задеплоено:** линия v0.6 запущена в **основной сети Polygon** (поколение 6). Адреса эталонного реестра и спутников — в [GUIDE.md → Current Release](../../docs/GUIDE.md#current-release); эталонный UI указывает на неё, а прежний реестр v0.5 вытеснен, но остаётся читаемым в Verify.

## Читаемая карточка — прямо в блокчейне

Ранние линии держали имена вне сети и хранили только числовой ID профиля. Для главного v0.6 делает наоборот: каждый паспорт теперь несёт небольшую **карточку** прямо on-chain — `title`, `authorName`, `shortDescription` и `domain`, — так что объект понятен даже без файла `.odpass`. Карточка записывается один раз при выпуске и **не имеет пути редактирования**: опечатка или переименование — это отзыв и перевыпуск. Она обязана байт-в-байт совпадать с теми же полями в `passport.json`; верификатор, нашедший любое расхождение, показывает паспорт как подделанный, а не просто «изменённый».

## Единый блок идентификации: `anchors[]`

Разрозненные поля v0.5 для пломб, дополнительных изображений, материалов, размеров и маркировок заменены одним расширяемым массивом `anchors[]` в `passport.json`. У каждого якоря есть тип (`photo`, `dimensions`, `materials`, `distinguishing_features`, `marks`, `file_hash`, `perceptual_hash`, `c2pa`, `nfc`, `numbered_seal`, `fingerprint`, `dna`, …), данные или их хэш и способ проверки. Весь массив фиксируется on-chain вторым хэшем `anchorsHash` плюс битовой маской присутствующих типов якорей — так блок идентификации можно проверить отдельно, например с компактного офлайн-носителя, без полного документа.

Контракт проверяет **жёсткий минимум опознания** при выпуске: физический объект должен нести хотя бы фото, размеры, материалы и отличительные особенности (и on-chain хэш основного изображения); цифровой — точный хэш файла. Паспорт без этого минимума не выпустится — потому что паспорт без фотографий и измерений ничего не доказывает про объект перед вами. Криптографическая пломба (NFC / нумерованная) теперь **опциональна** поверх минимума, а не обязательна.

## История «только дописывается»

v0.5 позволял владельцам перезаписывать поля текущего состояния (статус, местонахождение, права, состояние, указатель повреждений). v0.6 убирает их все. Всё изменяемое теперь — **append-only событие**, записанное on-chain: смена статуса, местонахождение, права, состояние, повреждение, реставрация или произвольная заметка, каждое может опционально «заякорить» подписанный документ его хэшем. Текущее значение любого аспекта — просто последнее событие соответствующего вида; ничего не перезаписывается, история не теряется. Передачи владения и институциональные подтверждения живут в том же append-only слое.

Провенанс в ODP поэтому начинается с регистрации. История **до** выпуска намеренно не является структурированной частью стандарта — протокол не может её проверить, а притворство обратным создавало бы ложную уверенность.

## Дубликаты: репутация, а не вердикт

Ничто не мешает кому-то зарегистрировать собственный паспорт на подделку или на чужой объект. v0.6 не пытается заставить протокол решать, какой из двух конкурирующих паспортов «настоящий», и намеренно **не** требует глобальной уникальности хэшей (она блокирует только точные копии, а злоумышленникам даёт оружие «кто первый зарегистрировал»). Вместо этого верификатор показывает сигналы, нужные человеку: время регистрации, опубликованную личность выпускающего, институциональные подтверждения и активные флаги подозрения в подделке. Решение остаётся за людьми — на основе записи.

## Что куда переехало

| v0.5 | v0.6 |
|---|---|
| on-chain только числовой ID профиля | + карточка on-chain: `title`, `authorName`, `shortDescription`, `domain` |
| `sealType` / `sealHash` / `nfcPublicKey` / `nfcModel` | якоря `nfc` / `numbered_seal` |
| `imageHash2/3`, `imageUrl2/3` | якоря `photo` (без фиксированного лимита) |
| `currentState.*` + четыре перезаписывающих сеттера | append-only `recordPassportEvent` |
| `auxCommitment*` (указатель COA) | `documentHash` подтверждения или якорь-документ |
| `ndppCommitment*` | офлайн-носители сверяются напрямую с `dataHash` / `anchorsHash` |
| `physical.seal` / `image` / `images` в JSON | `anchors[]` |

Профили (C/B/P/M), месячные лимиты выпуска, делегирование mint-агенту, спутники relations / proof / counterfeit-concern, отзыв, передача владения и обновление URL по модели не изменились.

## Под капотом

Эталонный реестр, его связанная библиотека и парные спутники переписаны под модель 0.6. Удаление шести перезаписывающих функций и большого куска структуры с лихвой окупает новые поля карточки и якорей: основной контракт теперь компилируется в **13 309 байт** против лимита EIP-170 в 24 576 байт — примерно половина бюджета свободна для будущей работы над протоколом (например, опциональной аттестации автора). Эталонный CLI выпуска (`chain/tools/mint.py`) и веб-потоки создания / проверки / управления строят и проверяют форму v0.6 от начала до конца.

Линия 0.x также несёт **`freeze()`** — предохранитель только для деплоера: он необратимо останавливает все записи в реестр (чтение продолжает работать), чтобы заброшенный экспериментальный деплой не накапливал новые записи. Это защита только альфа-линии; в **v1 её планируется убрать** — реестры должны жить без привилегированного рубильника.
