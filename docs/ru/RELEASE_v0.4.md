# Object Digital Passport — примечания к релизу · v0.4

Здесь описана **линия v0.4** в ветке **`main`**: **on-chain** поколение **4** (опциональный спутник **`ODPCounterfeitConcern`**), **статические страницы** (WalletConnect, восстановление сессии), **SPEC / документация** и **локализация**. Нормативные правила протокола — в **[`SPEC.md`](../../SPEC.md)** (английский оригинал: [`../../../SPEC.md`](../../SPEC.md)).

**Деплой:** эталонные **адреса Polygon** в [`../../../README.md`](../../README.md) и `chain/deploy/deployments/polygon.json` (историческая раскладка) рассчитаны на **поколение 4** (байт **`CONTRACT_VERSION` = 4**), с которым работают **`NET.*`** на страницах. При своём реестре задайте **`NET.contract`**, **`NET.docAnchor`**, **`NET.counterfeitConcern`** и при необходимости **`previousContracts`** (Verify) под **сеть + адрес + ABI**.

## Исправление реестра — UTC-месяц в `ODP-…` / `PRF-…` (почему линия остаётся **v0.4**)

**В чём была проблема:** в первом эталонном варианте поля `year` и `month` для `mintDigital` / `mintPhysical` (и для `submitProof`) проверялись только на диапазон. Вызывающий мог передать произвольную пару «календаря» (например **2000-01**) и получить **`ODP-2000-01-…`**, хотя блок по времени относился к другому месяцу — жёсткий абьюз человекочитаемого префикса.

**Что сделано:** контракт теперь требует, чтобы эти аргументы совпадали с **григорианским UTC** годом и месяцем **`block.timestamp`** (реализация — **`ODPPassportLib.utcYearMonthFromTimestamp`**; несовпадение → **`EC(68)`**). То же для минта через extension и для **`submitProof`** (префикс **`PRF-YYYY-MM-…`**). В веб-минте используются **UTC** (`getUTCFullYear` / `getUTCMonth+1`), чтобы совпадать с проверкой на чейне. Нормативно — **[`SPEC.md`](../../SPEC.md)** (§2, §8, §9).

**История деплоя:** сначала был задеплоен реестр **v0.4**; особенность **времени в названии** ID была замечена **сразу**. Этот ранний деплой **заморожен** (новые минты туда не направлять), **эталонный байткод и SPEC** обновлены под привязку к UTC. Так как несоответствие выявили до того, как линию считали стабильной для продакшена, **номер линии остаётся v0.4**: упакованный **`CONTRACT_VERSION` = 4** не меняется; отдельного перехода на **0.5** только из-за этого исправления нет. Старые деплои поколения 4 без проверки — отдельные реестры; всегда сопоставляйте **адрес + ABI**.

## On-chain (EIP-170)

- Упакованный **`CONTRACT_VERSION` = `4`** при минте и в **`submitProof`** (та же форма tuple, что у поколения **3**). Основной реестр — в лимите **24 КиБ**.
- Из эталонного байткода основного реестра убраны публичные геттеры **`SPEC_*`**, **`MONTHLY_LIMIT_*`**. Ориентируйтесь на **`CONTRACT_VERSION`**, **`getRemainingMints`** и лимиты **C = 1000**, **B = 100_000** в SPEC / исходнике.
- **`ODPPassportLib`**: NFC только **`NTAG424DNA_TT`**. Добавлены **`utcYearMonthFromTimestamp`** и проверка UTC-месяца минта; **`EC(83)`** при неподдерживаемом диапазоне времени; **`EC(68)`**, если `year`/`month` минта или proof не совпадают с UTC-календарём блока.
- **`ODPCounterfeitConcern`** — спутник: **`raiseCounterfeitConcern`**, **`clearCounterfeitConcern`**, **`getCounterfeitConcern`** (**P** и **M**); снять может только тот профиль, который поднял флаг. В конструкторе задаётся адрес **`ObjectDigitalPassport`**.

### Ошибки спутника (`ODPCounterfeitConcern`)

| Код | Смысл |
|-----|--------|
| **80** | Уже активно |
| **81** | Не активно |
| **82** | Снятие не авторизовано |

## Веб (`NET.*`, WalletConnect, сценарии)

- **`NET.counterfeitConcern`** — опциональный адрес спутника (тот же **`NET.contract`**). Помощники в **`../../../web/odp-contract.js`**.
- Лимиты минтов в UI: при отсутствии геттеров на чейне — запасные значения **1000** / **100_000** (см. SPEC).
- **WalletConnect v2** на страницах Профиля и Паспорта; конфиг **`../../../web/odp-wc-config.js`**, сборка бандла — см. **[`../../../docs/V0.4.md`](../../docs/V0.4.md)** и каталог **`web/`**.
- **Сессия:** после перезагрузки или перехода между `passport.html` и `creator.html` сессия WalletConnect восстанавливается, когда это поддерживается провайдером.
- **Паспорт (P / M):** опциональная **институциональная аттестация** уже существующего паспорта (хэш файла + опциональный URL); при подключённом спутнике — **подозрение на подделку** (структурированный хэш, без произвольного текста в сети). Строки: **`../../localization/en/passport.json`**, **[`passport.json`](https://github.com/object-digital-passport/object-digital-passport.github.io/blob/main/frontend/localization/ru/passport.json)** (RU).
- **Verify:** инструмент **аудита P-аффилиации** (только чтение: родитель, метки join/detach), если реестр отдаёт **`getPAffiliationAudit`**. Панель «назад + название инструмента» оформлена для белых карточек в синей теме.
- **SPEC / URI** — см. **`../../../SPEC.md`** и русский **`SPEC.md`** в этой папке.
