# Как участвовать

Спасибо, что заглянули. Первый вклад не обязан быть большим.

**Этот репозиторий — стандарт**: `SPEC.md`, контракты, схема, векторы. Эталонный сайт — [отдельный репозиторий](https://github.com/object-digital-passport/object-digital-passport.github.io) со своими задачами. Полезная проверка: если другой реализации тоже пришлось бы измениться — сюда; если сайт может починить это сам и остаться соответствующим — туда.

## Найдите, чем заняться

- [**`good first issue`**](../../../issues?q=is%3Aissue+is%3Aopen+label%3A%22good+first+issue%22) — небольшая, подготовленная, с условием готовности. Начинайте отсюда.
- [**`help wanted`**](../../../issues?q=is%3Aissue+is%3Aopen+label%3A%22help+wanted%22) — нужна помощь; **не обязательно простая задача**.
- **`ready to work`** — объём согласован, открытых вопросов проектирования нет.
- **`mentor available`** — сопровождающий ответит на вопросы прямо в задаче.
- **`needs info`** — не готова. Не берите.

## Язык (GitHub и сообщество)

**Задачи, pull request и ответы сопровождающих на GitHub — по-английски**, чтобы все в сообществе
читали одну ветку обсуждения. Нормативная спецификация — [`SPEC.md`](../../SPEC.md) (английский).
Переводы в [`frontend/localization/`](https://github.com/object-digital-passport/object-digital-passport.github.io/tree/main/frontend/localization)
**в репозитории сайта** справочные; обсуждение, меняющее протокол, всё равно ведётся по-английски
на GitHub.

### Документация переводится на русский, и это проверяет CI

У каждого документа этого репозитория есть русская версия в [`docs/ru/`](.) — либо записанная
причина, почему её нет. Запись ведётся в [`docs/TRANSLATIONS.md`](../TRANSLATIONS.md), а
`tools/check-translations.mjs` читает её отдельным заданием CI.

Отсюда три правила:

1. **Нормативен английский.** Если перевод расходится с английским текстом, ошибка в переводе.
   Об этом написано сверху в каждом русском файле.
2. **Добавили английский документ — добавьте строку.** CI падает на документе, который не учтён
   ни одной строкой: строка — это место, где вы решаете, переводится он, запланирован или
   намеренно не переводится. То же касается нового файла в `docs/ru/`.
3. **Меняете английский документ — проверьте его перевод.** Задание сообщает, каких
   идентификаторов, присутствующих в английском, нет в русском: адреса, строки `v0.N`, имена
   полей и кодов статуса. Пока этот отчёт не роняет сборку, потому что описывает бэклог старше
   самой проверки, — не добавляйте в него нового.

Имена, которые читает машина, не переводятся никогда: `dataHash`, `anchorsHash`, `passportId`,
`unitKey`, `anchorTypesMask`, `.odpass`, а также форматы `ODP-…` / `C-…` / `B-…` / `P-…` / `M-…`.
Переведённый идентификатор — это файл, который перестаёт проходить проверку.

Переводы на **другие** языки приветствуются и ведутся отдельно — см. открытые задачи.

## С чего начать
**Разрешение начинать не требуется.** Короткий комментарий «беру» нужен только чтобы двое не делали одно и то же. Если бросили — скажите, это нормально и никто не в обиде.

## Запустите то, что нужно

Для большинства задач по документации ставить ничего не надо. Для остальных:

```sh
git clone https://github.com/object-digital-passport/specifications.git
cd specifications

cd chain && npm install && npm test   # 103 теста Hardhat
node tools/check-profile-links.mjs    # ссылки в профиле организации
node chain/tools/lint_release_notes.mjs
```

## Перед предложением изменений

- Изменение соответствует списку **Done when** из задачи.
- Проверки выше проходят.
- В предложении только то, о чём просила задача, — без попутного переформатирования.
- В описании указано `Fixes #123`.

| Область | Заметки |
|--------|---------|
| **`SPEC.md`** | Ломающие изменения требуют обсуждения; зафиксируйте версию спецификации для реализаторов. |
| **`chain/contracts/`** | Неизменяемость on-chain: многие исправления — **новый деплой** и линия версий — укажите в PR. |
| **`schema/`** | JSON Schema, примеры соответствия и контрольные векторы. `registration.*` в `passport.json` обязаны оставаться **только в UTC** (без локальной зоны IANA устройства; в `localIso8601` только `+00:00`) — [SPEC.md](../../SPEC.md) (момент регистрации). |
| **`chain/deploy/`** | Hardhat; не коммитьте приватные ключи. |
| **`chain/tools/`** | Python CLI; новые флаги документируйте в `--help` или README. |
`main` принимает только предложения изменений, и CI должен быть зелёным. Подробности в [`.github/BRANCH_PROTECTION.md`](../../.github/BRANCH_PROTECTION.md).

## Язык

**Задачи, предложения изменений и обсуждения ведутся по-английски**, чтобы все читали одну ветку. Это не оценка чьего-то языка, а правило о том, где происходит разговор.

**Нормативен только английский `SPEC.md`.** Всё в `docs/ru/` и любой другой перевод — информационные: где перевод расходится со спецификацией, ошибка в переводе.

## Где что лежит

| | |
|---|---|
| `SPEC.md` | Стандарт. Ломающие изменения — сначала обсуждение |
| `chain/contracts/` | Solidity. Многие исправления требуют **нового развёртывания**, а не заплатки — скажите об этом в предложении |
| `schema/` | JSON Schema, примеры, контрольные векторы |
| `chain/tools/`, `tools/` | Инструменты на Node ESM |
| `docs/`, `docs/ru/` | Всё остальное и русский перевод |

Никогда не коммитьте приватный ключ. Место, где эта ошибка случается, — `chain/deploy/`.

## Застряли?

**Спрашивайте в той задаче, над которой работаете.** Это ожидаемо, и особенно уместно, если:

- не находите код, о котором говорит задача;
- не запускается проверка;
- список **Done when** читается несколькими способами — значит он написан плохо, и мы хотим об этом знать.

## Рецензирование

Замечания — обычная часть участия, а не приговор. Сопровождающий постарается объяснить не только что, но и почему.
