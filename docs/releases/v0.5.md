# ODP v0.5 — deployed, never released

ODP is a free, open digital passport for real objects — art, limited runs, archives — that anyone can verify. Forever.

**New here?** [What this is](https://github.com/object-digital-passport/specifications#readme) · [Verify something — free, no wallet](https://object-digital-passport.github.io/verify.html)

**There is no GitHub release for this version, on purpose.** The contract was deployed to the Polygon network and then not tagged, because the design turned out to be wrong in a way worth fixing rather than shipping. This page exists so that decision is on the record instead of being a gap in the list.

## What changed

- A clearer split between the parts of a passport that are fixed forever and the parts that change over time.
- A better way to describe objects that are physical, digital, or both at once.
- Smaller offline payloads, so a passport fits on a printed carrier.

It let the owner of a passport **overwrite** its current state — status, location, rights, condition — in place. That is convenient, and it quietly destroys the thing the registry exists for: a record that can be rewritten is worth whatever the last person to write it says. Publishing a release around that would have meant advertising a design already scheduled for removal. v0.6 replaced overwriting with entries that can only be added.

## Do I need to do anything?

- **You already registered a passport here** — it still verifies, and the check page still finds it. Nothing was abandoned. But this registry **cannot be switched off**: the mechanism for stopping writes was dropped in this version to fit the contract inside the size limit the network enforces, and restored in v0.6. Its retirement is a convention, not a lock.
- **You are about to register one** — use v0.6.
- **You run your own copy** — use v0.6.

Alpha. Each version is a separate registry and passports do not move between them, so anything registered here is a record on that version's registry and nowhere else. For work you need to last decades, wait for v1 — target January 2027.
