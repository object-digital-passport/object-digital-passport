# NFC-пломбы

> [🇬🇧 English](NFC-Seals) · 🇷🇺 **Русский**

Физическая пломба связывает паспорт с физическим объектом. ODP поддерживает номерные защитные пломбы (проверяются глазами) и **NFC-крипточипы** — сейчас это NXP **NTAG 424 DNA** и вариант **TagTamper** (фиксирует, отклеивали ли пломбу).

## Что на самом деле доказывает NFC-проверка (будьте честны с собой)

С v0.6 спецификация определяет два профиля проверки с очень разными гарантиями:

| | **Профиль A** — опубликованный ключ (legacy) | **Профиль B** — SDM с проверкой у издателя (рекомендуется для ценного) |
| --- | --- | --- |
| Как работает | AES-ключ чипа опубликован в блокчейне; любой телефон выполняет challenge-response | Ключ остаётся **секретом издателя**; каждое прикладывание генерирует свежий одноразовый код (CMAC + счётчик), который проверяет сервис издателя |
| Что значит PASS | Тег был запрограммирован публично известным ключом | Именно это прикладывание сделано чипом с секретным ключом, и это не повтор |
| Клонируется? | **Да** — ключ публичен, любой запишет его на чистый чип. Считайте индикатором присутствия | **Нет**, пока ключ издателя не утёк |
| Нужен интернет? | Нет | Да (сервис проверки издателя) |

Правило: для дорогих объектов просите издателя использовать **Профиль B**. Профиль A — удобство, а не доказательство подлинности; верификатор, показывающий «подлинно» только по Профилю A, вас обманывает.

Подробности: [матрица гарантий в спецификации](https://github.com/object-digital-passport/object-digital-passport/blob/main/SPEC.md#seal-verification-profiles-and-assurance-matrix-normative).

## Поддержка телефонов

### Android

Полная поддержка уже сегодня: чтение, EV2 challenge-response, статус TagTamper и прошивка чипов через [Android-компаньон](https://github.com/object-digital-passport/odp-android-companion). Chrome на Android также умеет Web NFC для простого чтения.

### iPhone

- **Проверка пломбы Профиля B (SDM) — работает из коробки.** Чип отдаёт обычный URL с одноразовым кодом; iPhone XS и новее читают NFC-теги фоном — приложили объект, открылась ссылка проверки, готово. Приложение не нужно. (iPhone 7–X читают через приложение с Core NFC.)
- **Challenge-response Профиля A и статус TagTamper — нужно нативное iOS-приложение.** iOS даёт приложениям низкоуровневый доступ (APDU по ISO 7816 через Core NFC, iOS 13+), так что iOS-компаньон технически возможен — его просто пока нет. В Safari нет Web NFC, браузерный сценарий невозможен.
- **Прошивка чипа с iPhone (запись ключей, включение SDM/TagTamper)** — та же история: только нативное приложение. Сегодня издатели прошивают чипы Android-компаньоном.

Практический вывод: **Профиль B — самый дружелюбный к iPhone вариант**: фоновое чтение тега покрывает весь сценарий проверки для конечного пользователя.

## Издателям: обязательный порядок

1. Прошейте чип **до** минта (загрузите ключи, включите TagTamper, если используется).
2. Отсканируйте живой чип и импортируйте его данные в форму паспорта — это защищает от публикации неверного UID или ключа в блокчейне.
3. Минтите; затем запишите на чип URL проверки.

Полный сценарий: [ISSUER_NFC_FLOW.md](https://github.com/object-digital-passport/object-digital-passport/blob/main/docs/ISSUER_NFC_FLOW.md).
